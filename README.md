# P2 LED-Matrix Morphing Digits
Morphing-digit clocks, counters and values for HUB75 RGB LED matrix panels on the P2

### Pages: README | [Change Log](ChangeLog.md)

I first ran across a [morphing clock project at the Hackaday website](https://hackaday.com/2018/07/10/morphing-digital-clock-will-show-you-a-good-time/) when I was researching how to drive LED Matrix panels. I noted this, and then moved on to making the [LED Matrix driver for the P2](https://github.com/ironsheep/P2-HUB75-LED-Matrix-Driver). Later, after creating the HUB75 Adapter PCB and more work on the driver, I took a short break and looked into how to drive this morphing.

This project is my nod to **Hari Wiguna**'s [HariFun #165 video](https://www.youtube.com/watch?v=_DddhMh6kJc). Each digit is drawn as one continuous stroke with a round pen. When a digit changes, the parts of the stroke that leave snake away or slide aside, and the parts that arrive grow in, following a table of animations generated by a Python script from the digits' shapes.

This is an add-on to the **P2 HUB75 LED Matrix Driver** for the Parallax Propeller 2 [P2 or P2X8C4M64P]. It contains only the morphing-digit objects and their demos; the driver itself is not included.

Demo: [A Video of this project in action](https://youtu.be/-zx-_Z1aoWY) (it shows the 2021 version).

```text
Latest Updates:
14 Oct 2026 - v2.0.0
- Digits drawn as one round-pen stroke at any size and thickness, anti-aliased, with time-based motion at the display's refresh rate
- Place clocks, counters and values anywhere on the display, sized to the area you give them, in any of four rotations
- Three demos: the 2021 demo rebuilt, a showcase, and a minimal clock to copy from
```

## The Project

The point of this project is digits that change the way Hari's do: smoothly, one stroke at a time, never by blinking from one number to the next. A digit is the morphing-digit figure drawn with a round pen: rounded corners inside and out, no gaps between its parts, and the same shape at every size. Each group of digits is a **clock** (MM:SS, HH:MM or HH:MM:SS, 24 or 12 hour, in real time or stepped), a **counter** (counting up or down), or a **value** your code sets. You choose each group's area, color, stroke, rotation and pace.

What you need:

- **P2 HUB75 LED Matrix Driver v4.0.0 or later.** Earlier versions do not compile with this code (v4.0.0 changed how the driver starts and is configured). Get it from the [driver's Releases page](https://github.com/ironsheep/P2-HUB75-LED-Matrix-Driver/releases).
- A P2 board with the [P2 Eval HUB75 Adapter](https://www.parallax.com/product/p2-eval-hub75-adapter-board/) and HUB75 panels the driver supports. The demos lay themselves out for a single 64 x 32, 64 x 64 or 128 x 64 panel, or a larger display.

I develop this on four 128 x 64 ICN2037 panels in a 2 x 2 grid (256 x 128 pixels), 8-bit color, at 335 MHz. On that display every scene of the showcase demo, including nine groups changing at once, runs at the display's full refresh rate of 71 frames per second.

## Installation

1. Put the HUB75 driver v4.0.0 (or later) files in a folder.
1. Configure the driver for your panels in its **isp_hub75_hwPanelConfig.spin2** (the `DISP0_*` settings), following the driver's documentation. This project does not ship that file, so copying our files in never overwrites your configuration.
1. Download **p2-obex-morphing-digits-v2.0.0.zip** from this project's [Releases page][releases], unzip it, and copy the files from its folder into the same folder. None of them shares a name with a driver file. (From a clone of this repository, copy `Src/isp_hub75_morph*.spin2` and `Src/demo_hub75_morph*.spin2` instead.)
1. Compile and run a demo, e.g. `pnut-ts demo_hub75_morphClock.spin2`, then download it to your P2.

| Demo | File | What it shows |

On a display larger than 128 x 64 it is drawn at a whole-number multiple of its size. |
| Showcase | **demo_hub75_morphShowcase.spin2** | The library's range in a loop of scenes: a clock filling the display, a thick clock over thin counters, a "splatter" of nine groups of every type, size, color, stroke and rotation, a status panel (time of day, uptime, a countdown and the live frame rate), and one counter at all four rotations. Between scenes every group morphs out and the next morphs in. The library version morphs on at start-up. |

## Using morphing digits in your own code

Conceptually, each group draws itself whenever you call its `animate()`, at the position its moves have reached at the time you pass it. Your program runs one loop: read the time, give the groups any new values, let each draw, and commit the frame to the panels. The commit waits for the driver, so the loop runs at the display's refresh rate.

Include the objects in your project:

```spin2
OBJ
    display     : "isp_hub75_display"
    hub75Bffrs  : "isp_hub75_hwBufferAccess"
    color       : "isp_hub75_color"
    timeBase    : "isp_hub75_morphTime"
    clock       : "isp_hub75_morphCounters"
```

Start the driver, place a group in an area of the display, and run the frame loop:

```spin2
PUB start() | chainIdx, nowMs
    display.start(display.HUB75_ADAPTER_1)              ' configures the adapter and starts the driver
    display.clearScreen()
    chainIdx := hub75Bffrs.indexForHub75ChainId(hub75Bffrs.HUB75_ADAPTER_1)
    ' a real-time HH:MM clock filling the display, starting at 12:00 (a clock's value is seconds since midnight)
    clock.placeGroup(hub75Bffrs.HUB75_ADAPTER_1, 0, 0, hub75Bffrs.maxDisplayColumns(chainIdx), hub75Bffrs.maxDisplayRows(chainIdx), clock.GRP_CLOCK, clock.LAYOUT_HH_MM, clock.ROT_0, color.cOrange, 12 * 60 * 60)
    timeBase.reset()
    repeat
        nowMs := timeBase.update()                      ' the frame's time, shared by every group
        clock.animate(nowMs)                            ' a real-time clock advances itself and draws its moves
        display.commitScreenToPanelSet()                ' show the frame; this waits for the driver, so it paces the loop
```

That's all there is to it; this is **demo_hub75_morphClock.spin2**. A group takes the largest digits that fit its area and centres itself in it. For more groups, declare an array of `isp_hub75_morphCounters` objects, place each in its own area, and call each one's `animate()` in the loop. A counter steps when you call its `nextTimeCycle()` (the demos do it when `isHoldComplete(nowMs)` says its last change has been on show long enough); a value group shows what you give `setValue()`; a clock can be set at any time with `setTime()`.

Every call that can be refused returns a status: `SUCCESS` (0) or a negative code from **isp_hub75_morphStatus.spin2**, and a refused call changes nothing. Check the status of `placeGroup()`: an area that is too small, off the display, or overlapping another group's area is refused.

To move a group, call `removeGroup()`, keep animating until `isPlaced()` is FALSE (its digits morph out), then place it again. The stroke settings below (thickness and cross-section) apply at the next placement; the others apply at once.

## Reference

`placeGroup(adapter, left, top, width, height, type, layout, rotation, color, initialValue) : status, usedWidth, usedHeight`

| Group type | What it shows | Layouts |
|---|---|---|
| `GRP_CLOCK` | a time of day or an elapsed time; its value is seconds | `LAYOUT_MM_SS`, `LAYOUT_HH_MM`, `LAYOUT_HH_MM_SS` |
| `GRP_UP_COUNTER` | counts up one per `nextTimeCycle()`, 9..9 wraps to 0 | `LAYOUT_1_DIGIT` .. `LAYOUT_6_DIGITS` |
| `GRP_DOWN_COUNTER` | counts down one per `nextTimeCycle()`, 0 wraps to 9..9 | `LAYOUT_1_DIGIT` .. `LAYOUT_6_DIGITS` |
| `GRP_DIGITS` | the value your code gives `setValue()` | `LAYOUT_1_DIGIT` .. `LAYOUT_6_DIGITS` |

| Rotation | Meaning |
|---|---|
| `ROT_0` | not turned |
| `ROT_90` | turned 90 degrees clockwise |
| `ROT_180` | upside down |
| `ROT_270` | turned 90 degrees counter-clockwise |

Rotation turns the group within its area; the display's own mounting is the driver's setting, and the two combine.

| Setting | Default |
|---|---|
| `setThickness(pixels)` / `useAutoThickness()` | the stroke is sized with the digits, about a quarter of a segment's length |
| `setCrossSection(morphMask.SECTION_FLAT or SECTION_TUBE)` | `SECTION_FLAT`, even brightness across the stroke |
| `setProfile(timeBase.PROFILE_TAIL or PROFILE_EDGE)` | `PROFILE_TAIL`, a moving end that fades over a short tail |
| `setTailLength(pixels)` | a quarter of a segment's length |
| `setMoveDuration(ms)` | 300 ms per move, at any size |
| `setHoldDuration(ms)` | 200 ms on show before `isHoldComplete()` |
| `setEasing(timeBase.EASE_LINEAR or EASE_SMOOTH)` | `EASE_LINEAR` |
| `setClockHours(HOURS_24 or HOURS_12)` | `HOURS_24` |
| `setClockMode(CLOCK_REAL_TIME or CLOCK_ACCELERATED)` | `CLOCK_REAL_TIME`, one second per second |

| Status code | Value | Status code | Value |
|---|---|---|---|
| `SUCCESS` | 0 | `E_AREA_TOO_SMALL` | -14 |
| `E_OUT_OF_RANGE` | -1 | `E_AREA_OVERLAP` | -15 |
| `E_UNKNOWN_EASING` | -2 | `E_TOO_MANY_GROUPS` | -16 |
| `E_BAD_THICKNESS` | -3 | `E_BAD_AREA` | -17 |
| `E_THICKNESS_TOO_LARGE` | -4 | `E_UNKNOWN_ADAPTER` | -18 |
| `E_UNKNOWN_CROSS_SECTION` | -6 | `E_VALUE_OUT_OF_RANGE` | -19 |
| `E_MASK_TOO_LARGE` | -7 | `E_NOT_PLACED` | -20 |
| `E_UNKNOWN_PROFILE` | -8 | `E_UNKNOWN_CLOCK_SETTING` | -21 |
| `E_BAD_TAIL_LENGTH` | -9 | `E_WRONG_TYPE` | -22 |
| `E_BAD_COMMAND` | -10 | `E_ALREADY_PLACED` | -23 |
| `E_UNKNOWN_ROTATION` | -11 | | |
| `E_UNKNOWN_TYPE` | -12 | | |
| `E_UNKNOWN_LAYOUT` | -13 | | |

**How many groups fit.** Each group costs about 9.2 KB of hub RAM, and the driver's buffers take most of the rest: with the quad's 8-bit driver, the showcase fits nine groups. A program with more code of its own fits fewer, and a smaller display leaves room for more (up to `MAX_GROUPS`, 10, placed at once). The compiler refuses a build that does not fit, so you find out at compile time.

**More than one display.** Placement takes the adapter, so groups can be placed on a second or third HUB75 adapter. This is designed for but not tested.

**Coming from the 2021 code?** `placeGroup()` replaces `placeDigitGroup()`: you give it an area instead of a position and segment length, and it sizes the digits to fit. The random-digits group type is gone; give a `GRP_DIGITS` group random values with `setValue()` (the demos show how). `animate(nowMs)` replaces `animateStep()`.

## Testing on the board

The repository holds the test programs we run on the board before every release (they are not in the release zip). Each reports through debug output; run it headless and read its log:

```bash
# compile one test program with DEBUG and run it on the board; the log lands in Src/logs/
cd Src
pnut-ts -d test_hub75_morph<Area>.spin2
pnut-term-ts --headless -p <your P2's USB serial> -r test_hub75_morph<Area>.bin --end-marker --timeout 240
```

A program passes when its log ends `RESULT   PASS`.

| Gate | Programs | What it proves |
|---|---|---|
| Range | **test_hub75_morph**Smoke, Time, Motion, Color, Mask, Render, Rotate, Place, Values, Range | 294 behaviour checks: layout in six area sizes, all four rotations, every clock and counter rollover, masks, color ramps, the time base, interrupted moves, overlap and removal, and every status code |
| Performance | **test_hub75_morphPerf** | every showcase scene holds 60 frames per second or more, and the drawing work per frame stays within its recorded figures |

## How the animations are made

The animation table comes from **Generator/pymorph.py**, a simple Python 3 script. It iterates over every digit transition (0->1, 5->2, and so on) and, for each, studies the parts of the digit turning on and off and the parts they touch, and from that decides which animation each part performs: parts that turn off animate turning off, and parts that turn on animate turning on.

We letter-name the seven parts of a digit so we can identify them:

```text
   -- A --
  |       |
  F       B
  |       |
   -- G --
  |       |
  E       C
  |       |
   -- D --
```

Studying Hari's video shows two kinds of moves. A **snake** adds pixels to the end of a part, filling it, or removes them, hiding it; it can run left-to-right, right-to-left, top-to-bottom or bottom-to-top. A **column** move slides a whole left-side part (E or F) left or right. Each table entry encodes the part, its end state (on or off), and its animation (four snakes, two column moves).

The script needs Python 3 plus the `tzlocal` and `colorama` packages (`pip install tzlocal colorama`):

```bash
./Generator/pymorph.py -o animationTable.out    # -v verbose, -d debug
```

Its output is copied into the `fmN_M` entries of the `DAT` section of **isp_hub75_morph7seg.spin2**. **Docs/transition-table.out** is a copy of the latest output.
